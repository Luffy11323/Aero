Capabilities

Built for real ERP work

🧠
ChatGPT is the brain
No AI keys on your server. ChatGPT handles all planning, reasoning and natural language — your backend is a pure, stateless ERP executor.
🔗
Multi-step plan execution
Send a steps[] array. Outputs of step N are automatically passed to step N+1 via $step_1.name references. Full chain without manual IDs.
🛡️
Human-in-the-loop approval
High-risk actions (submit, cancel, delete) are flagged in the OpenAPI spec. ChatGPT warns you before every irreversible step.
🔍
Schema-aware payloads
/schema/{doctype} lets ChatGPT discover required fields before building any payload. It never guesses field names or supplier names.
📋
Full audit trail
Every action is logged with timestamp, request ID, action name and result. Query /audit at any time for a complete history.
⚡
Stock & finance guardrails
Item validation and stock availability checked before any delivery note or order is created. Financial DocTypes always get flagged for approval.

API Reference

REST endpoints

POST /execute Execute one or multiple ERP actions sequentially ▶

Single action or multi-step plan. Use $step_N.field to chain outputs between steps.

{
  "steps": [
    {
      "action": "create_document",
      "description": "Create Purchase Order",
      "data": {
        "doctype": "Purchase Order",
        "fields": { "supplier": "Acme Corp" }
      }
    },
    {
      "action": "submit_document",
      "description": "Submit the PO",
      "data": {
        "doctype": "Purchase Order",
        "name": "$step_1.name"
      }
    }
  ]
}
POST /query Read-only document list with filters ▶ 
{
  "doctype": "Item",
  "filters": [["disabled", "=", 0]],
  "fields": ["name", "item_name", "item_group"],
  "limit": 50
}
GET /schema/{doctype} Discover field definitions for any DocType ▶
GET /report/{report_name} Run a named ERPNext report ▶
GET /health ERP connectivity status ▶
