Developer Docs

ChatGPT is the brain. Your Flask server is the executor. No AI keys. Pure ERP automation.

This server exposes a clean REST API that a ChatGPT Custom GPT uses to interact with ERPNext. You describe a business problem in plain language — the GPT plans the steps, explains each one, asks for your approval, then calls /execute with a structured multi-step payload.

Step outputs chain automatically via $step_N.field references. No session state. No AI keys on your server. Stateless, auditable, and built for human-in-the-loop approval.

ℹ Note
This server requires no AI API keys. All intelligence runs inside ChatGPT. Deploy this server, paste /openapi.json into your Custom GPT's Actions config, and it's live.

Architecture

The system is split into two clean layers:

1

User → ChatGPT (natural language)

"Create a purchase order for 100 units of BOLT-001 from Acme Corp and submit it."

2

ChatGPT → /schema + /query (discovery)

Before building any payload, ChatGPT fetches the DocType field schema and verifies that the supplier exists by querying the ERP directly.

3

ChatGPT → User (plan + approval gate)

The GPT presents a numbered plan with risk levels. High-risk steps (submit, cancel, delete) get a ⚠️ warning. Nothing executes until you say yes.

4

ChatGPT → /execute (execution)

All confirmed steps are sent in one request. The server executes them sequentially, passing outputs between steps via $step_N.name references.

5

Server → ChatGPT → User (results)

Results are returned to ChatGPT, which formats them in plain language and reports document names, errors, and next steps.

Setup & Deploy

Requirements

  • Python 3.11+
  • A running ERPNext / Frappe instance with API access
  • A publicly accessible URL for this server (Hugging Face Spaces, Railway, Render, etc.)
  • A ChatGPT Plus or Team account (for Custom GPTs)

Install & run

bash
pip install flask requests gunicorn

# Set environment variables
export ERP_URL=https://erp.yourcompany.com
export ERP_API_KEY=your_frappe_api_key
export ERP_API_SECRET=your_frappe_api_secret
export PORT=7860

# Development
python app.py

# Production (recommended)
gunicorn app:app --workers 4 --bind 0.0.0.0:7860 --timeout 120

POST/execute

The core endpoint. Accepts a single action or a steps[] array for multi-step plans. Steps run sequentially. Each step's output is stored in context and available to subsequent steps via $step_N.field references.

Single action

json
{
  "action": "check_stock",
  "data": {
    "item_code": "BOLT-001"
  }
}

Multi-step plan

json
{
  "steps": [
    {
      "action": "create_document",
      "description": "Create Purchase Order",
      "data": {
        "doctype": "Purchase Order",
        "fields": {
          "supplier": "Acme Corp",
          "items": [{ "item_code": "BOLT-001", "qty": 100 }]
        }
      }
    },
    {
      "action": "submit_document",
      "description": "Submit the Purchase Order",
      "data": {
        "doctype": "Purchase Order",
        "name": "$step_1.name"  ← references step 1 output
      }
    }
  ]
}

Response

json — success
{
  "ok": true,
  "total": 2,
  "results": [
    {
      "step": 1, "action": "create_document",
      "status": "success",
      "result": { "name": "PO-2025-00042", ... }
    },
    {
      "step": 2, "action": "submit_document",
      "status": "success",
      "high_risk": true,
      "result": { ... }
    }
  ]
}
json — partial failure
{
  "ok": false,
  "failed_step": 2,
  "message": "Stopped at step 2 (submit_document): ERP PUT failed: 403",
  "results": [ /* completed steps before failure */ ]
}

POST/query

Read-only. Query any ERPNext DocType with filters and field selection.

json — request
{
  "doctype": "Supplier",
  "filters": [["disabled", "=", 0]],
  "fields": ["name", "supplier_name", "supplier_group"],
  "limit": 20
}
FieldTypeDescription
doctypestring requiredERPNext DocType name
filtersarrayFrappe filter format: [["field", "operator", value]]
fieldsarrayFields to return. Default: ["name", "creation"]
limitintMax records. Default: 20

GET/schema/{doctype}

Returns all field definitions for a DocType. ChatGPT calls this before building any payload to ensure it uses correct field names and types.

example
GET /schema/Purchase%20Order

// Response
{
  "ok": true,
  "doctype": "Purchase Order",
  "fields": [
    { "fieldname": "supplier", "fieldtype": "Link", "reqd": 1 },
    { "fieldname": "schedule_date", "fieldtype": "Date", "reqd": 1 },
    { "fieldname": "items", "fieldtype": "Table", "reqd": 1 }
  ]
}

GET/report/{report_name}

Run any named ERPNext report. Pass filters as a URL-encoded JSON string.

example
GET /report/Stock%20Balance?filters={"company":"Acme Corp"}

GET/health

json
{
  "ok": true,
  "status": "healthy",
  "erp": { "ok": true, "detail": "connected" },
  "audit_entries": 142
}

GET/audit

Returns the last N audit log entries. Every action, success, and failure is recorded.

example
GET /audit?limit=50

{
  "ok": true,
  "total": 142,
  "entries": [
    {
      "ts": "2025-03-10T14:22:01Z",
      "event": "execute.create_document.done",
      "status": "ok",
      "request_id": "9f3a1b2c",
      "payload": { "step": 1, "data": { ... } }
    }
  ]
}

GET/openapi.json

Returns a live OpenAPI 3.1 spec including all endpoints, action enums, risk annotations, and step reference syntax documentation. Paste this URL directly into ChatGPT Custom Action's schema field — ChatGPT will auto-discover everything.

ℹ Auto-generated
The spec is generated dynamically from the running server, so it always reflects the current list of available actions and endpoints.

Step References

Use $step_N.field syntax in any data field to reference the output of a previous step. The server resolves these at runtime before calling the action handler.

example
{
  "steps": [
    {
      "action": "create_document",
      "data": { "doctype": "Sales Invoice", "fields": { ... } }
      // step 1 returns: { "name": "SINV-2025-00001", ... }
    },
    {
      "action": "submit_document",
      "data": {
        "doctype": "Sales Invoice",
        "name": "$step_1.name"  // resolved to "SINV-2025-00001"
      }
    },
    {
      "action": "create_document",
      "data": {
        "doctype": "Payment Entry",
        "fields": {
          "reference_name": "$step_1.name",  // reuse step 1
          ...
        }
      }
    }
  ]
}

Guide: Purchase Order Flow

A full example conversation with the ChatGPT agent:

Example prompt
"Create a purchase order for 100 units of BOLT-001 from Acme Corp, then submit it."

The agent will:

  1. Call GET /schema/Purchase Order to discover required fields
  2. Call POST /query with doctype: "Supplier" to verify Acme Corp exists
  3. Present a 2-step plan: create + submit, with risk levels
  4. Warn that submit is HIGH RISK (irreversible without amendment)
  5. Wait for your "go ahead" before calling POST /execute
  6. Report: "✅ PO-2025-00042 created and submitted."

Guide: Invoice & Payment

⚠ Financial documents
Sales Invoice, Purchase Invoice, Payment Entry, and Journal Entry always trigger a warning in the ChatGPT agent before execution. These affect your accounts and general ledger.
3-step plan example
{
  "steps": [
    { "action": "create_document", "data": { "doctype": "Sales Invoice", "fields": { ... } } },
    { "action": "submit_document", "data": { "doctype": "Sales Invoice", "name": "$step_1.name" } },
    { "action": "create_document", "data": {
        "doctype": "Payment Entry",
        "fields": { "payment_type": "Receive", "reference_name": "$step_1.name", ... }
    }}
  ]
}

Guide: Stock Check

Before any delivery or order involving items, use check_stock to verify availability:

json
{ "action": "check_stock", "data": { "item_code": "BOLT-001" } }

// Response
{
  "ok": true,
  "results": [{
    "status": "success",
    "result": { "actual_qty": 450, "reserved_qty": 100, "projected_qty": 350 }
  }]
}

Note: when create_document includes an items array, stock validation runs automatically — no need to add a separate check step.

Errors & Rollback

When a step fails, the server stops execution and returns all completed steps plus the error. The ChatGPT agent will present the failure and ask whether to retry, skip, or rollback.

error response
{
  "ok": false,
  "failed_step": 2,
  "message": "Stopped at step 2 (submit_document): ERP PUT failed: 403",
  "results": [
    { "step": 1, "status": "success", "result": { "name": "PO-2025-00042" } },
    { "step": 2, "status": "error", "error": "ERP PUT failed: 403 Forbidden" }
  ]
}
✕ No auto-rollback
The server does not automatically rollback completed steps. This is intentional — rollback of financial documents requires human judgement. The ChatGPT agent will suggest compensating actions (e.g. cancel_document) and ask you to confirm.
