Bulk Email Automation

EmailBlast Pro

A production-grade bulk email API built on FastAPI and Gmail SMTP. Upload an Excel or CSV list, configure per-row branding, pick a template, and fire — with live open tracking, warm-up scheduling, multi-account round-robin, and webhook callbacks.

◈ What is this API?

EmailBlast Pro is a background-job email sender. You POST a file and your Gmail credentials — it queues the job, sends emails asynchronously, and lets you poll live progress. Every email is sent through Gmail SMTP using your own App Password. Credentials are never stored.

◈ Features

  • Per-row branding — FromName, ReplyTo, BodyExtra, CTAUrl all settable per recipient in the file
  • 3 HTML templates — Plain text, Promo (dark hero + CTA button), Newsletter (editorial serif)
  • Open tracking pixel — 1×1 GIF at /track/open/{job_id}/{email}, live open rate in status
  • Round-robin SMTP — add multiple Gmail accounts, load distributed automatically
  • Warm-up mode — 11-day ramp schedule from 5 to 400 emails/day
  • Webhook callback — POST fired on job completion, compatible with n8n, Zapier, Make
  • Unsubscribe links — auto-appended to every email
  • HF Space secrets — GMAIL_USER/GMAIL_PASS read from env, never hardcoded
ℹ️
Base URL: https://frnklnwrld-emailblast-pro.hf.space
All endpoints return JSON. Gmail credentials are passed per-request or pre-loaded from HF Space secrets.
Getting Started

Quick Start

Send your first blast in under 3 minutes.

01

Prepare your file

Create an .xlsx or .csv with at minimum an Email column. Optionally add FromName, ReplyTo, BodyExtra, CTAUrl columns for per-row customisation.

02

Get a Gmail App Password

Go to myaccount.google.com/security → 2-Step Verification → App Passwords. Generate one for "Mail". Use this — never your real password.

03

POST to /send

Upload the file as multipart form data with your credentials and campaign settings. You'll receive a job_id immediately.

04

Poll /status/{job_id}

Every 2 seconds, poll the status endpoint for live sent count, open rate, errors, and a scrolling log. Status transitions: queued → running → done.

cURL Example

bash
curl -X POST https://frnklnwrld-emailblast-pro.hf.space/send \
  -F "file=@recipients.xlsx" \
  -F "gmail_user=you@gmail.com" \
  -F "gmail_pass=xxxx xxxx xxxx xxxx" \
  -F "subject=Hello from Our Store" \
  -F "default_from_name=Our Store" \
  -F "max_emails=50" \
  -F "template_name=promo"

JavaScript (fetch)

javascript
const fd = new FormData();
fd.append('file', fileInput.files[0]);
fd.append('gmail_user', 'you@gmail.com');
fd.append('gmail_pass', 'xxxx xxxx xxxx xxxx');
fd.append('subject', 'Hello from Our Store');
fd.append('default_from_name', 'Our Store');
fd.append('max_emails', '50');
fd.append('template_name', 'promo');

const res = await fetch('https://frnklnwrld-emailblast-pro.hf.space/send', {
  method: 'POST', body: fd
});
const { job_id } = await res.json();

// Poll for progress
const poll = setInterval(async () => {
  const s = await fetch(`/status/${job_id}`).then(r => r.json());
  console.log(s.sent, '/', s.total, '— opens:', s.open_rate);
  if (s.status === 'done') clearInterval(poll);
}, 2000);

File Format

Accepted formats: .xlsx and .csv. One row per recipient.

◈ Column Reference

ColumnRequiredDescriptionExample
EmailYesRecipient email address. Invalid formats are silently skipped.customer@gmail.com
FromNameOptionalDisplay name shown in the recipient's inbox. Falls back to default_from_name.Ahmed's Shop
ReplyToOptionalReply-To header. Where replies are directed. Can differ from the sender Gmail.ahmed@shop.pk
BodyExtraOptionalPer-recipient body text. Overrides the global body_extra form field for this row.Here's your exclusive offer…
CTAUrlOptionalPer-row CTA button URL. Only used by the promo template. Overrides global cta_url.https://shop.pk/offer/123

Example file

xlsx / csv
Email                  | FromName        | ReplyTo              | CTAUrl
-----------------------|-----------------|----------------------|---------------------------
customer1@gmail.com    | Ahmed's Shop    | ahmed@shop.pk        | https://shop.pk/sale
customer2@yahoo.com    | Sana Boutique   | sana@boutique.pk     |
customer3@hotmail.com  |                 |                      |  ← uses defaults
⚠️
Rows with invalid email formats (no @, no TLD, etc.) and duplicate emails within the same job are automatically skipped without stopping the job. Check the live log for skip messages.

Features

HTML Templates

Three built-in email templates — from plain text to fully designed HTML. Set via template_name in /send.

◈ plain

Simple plain-text email. Highest deliverability. Safest for cold outreach. No HTML, no images — just formatted text with an unsubscribe link appended.

◈ promo

Fully designed HTML email with a dark hero section (branded with FromName), body text, and a yellow CTA button linking to cta_url. Includes the tracking pixel and unsubscribe link in the footer. CTA URL can be overridden per-row via the CTAUrl column.

◈ newsletter

Editorial serif layout. Clean white background, masthead with FromName and the current month, body text, and a minimal footer. Suited for digest-style emails.

⚠️
All three templates automatically embed the tracking pixel (/track/open/…) and an unsubscribe link (/unsubscribe/…). These cannot be disabled.
Features

Open Tracking

Every email embeds a 1×1 invisible GIF that fires a request to the API when the recipient opens the email.

◈ How it works

  • Each email contains <img src="/track/open/{job_id}/{email}" width="1" height="1"/>
  • When the email client loads images, a GET hits /track/open/{job_id}/{email}
  • The server records {email, timestamp} in memory for that job
  • /status/{job_id} returns live opens count and open_rate
  • /analytics/{job_id} returns the full event list with timestamps
ℹ️
Open data is stored in-memory only — it resets if the HF Space restarts. For persistent analytics, fire a webhook on job completion and store the data externally.
Features

Round-Robin SMTP

Distribute sends across multiple Gmail accounts to avoid per-account daily limits.

◈ Setup

Pass additional accounts as a JSON array in the extra_accounts field alongside your primary gmail_user / gmail_pass:

json — extra_accounts field value
[
  { "user": "account2@gmail.com", "pass": "xxxx xxxx xxxx xxxx" },
  { "user": "account3@gmail.com", "pass": "xxxx xxxx xxxx xxxx" }
]

The API connects all accounts at job start, then distributes sends in a round-robin cycle: email 1 → account 1, email 2 → account 2, email 3 → account 3, email 4 → account 1, and so on. The log shows which account sent each email.

ℹ️
If an account fails to connect at startup it is skipped with a log entry — the job continues on remaining accounts. A job with zero valid connections is aborted with status: failed.

Features

Webhooks

Fire a POST callback when a job completes — connect to n8n, Zapier, Make, or your own backend.

◈ Payload

json — webhook POST body
{
  "job_id": "a1b2c3d4",
  "sent": 98,
  "errors": 2,
  "status": "done"
}

Pass the webhook URL in the webhook_url form field when calling /send. The request is fired once when the job transitions to done. Failures are logged but don't affect the job result.

n8n / Zapier / Make integration

Use a Webhook trigger node in n8n or a "Webhooks by Zapier" step — paste the generated URL into the webhook_url field. The completion payload can then trigger Slack notifications, Airtable updates, Google Sheets logging, or follow-up campaigns.

Error Handling

400
Bad Request
File missing an Email column, unreadable file format, or no SMTP credentials provided and no secrets configured.
404
Job Not Found
Returned by /status/{job_id} or /analytics/{job_id} when the job_id doesn't exist or the Space restarted (in-memory store cleared).
500
Server Error
Unexpected crash. Check HF Space container logs. Common causes: index.html not found, missing dependency.

Job-level failures (not HTTP errors)

SMTP connection failures and per-email send errors don't return HTTP errors — they're recorded in job.errors and the log array with a ✗ prefix. The job continues to the next recipient.

javascript — recommended polling pattern
async function pollJob(jobId) {
  const timer = setInterval(async () => {
    try {
      const r = await fetch(`${API_BASE}/status/${jobId}`);
      if (r.status === 404) {
        clearInterval(timer);
        console.error('Job not found — Space may have restarted');
        return;
      }
      const d = await r.json();
      updateUI(d);
      if (d.status === 'done' || d.status === 'failed') {
        clearInterval(timer);
      }
    } catch(e) {
      console.warn('Poll failed:', e); // keep retrying
    }
  }, 2000);
}

The full project is 5 flat files — no folders needed.

◈ HF Space file structure

file tree
EmailBlast_Pro/
├── app.py              ← FastAPI backend
├── index.html          ← UI (served at /)
├── Dockerfile          ← SDK: docker, port 7860
├── requirements.txt
└── README.md           ← HF Space card (YAML frontmatter)

◈ Dockerfile

dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 7860
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "7860"]
⚠️
HF Space free tier sleeps after 48 hours of inactivity. The first request after sleep takes ~30s to wake. Background jobs that are in progress when the Space sleeps will be lost — in-memory job state is not persisted.

◈ Vercel (UI only)

The email.html (this file) is deployed as a static page at https://aero-woad.vercel.app/email.html. It links back to the HF Space API. No build step needed — just drag-drop or push via GitHub.
